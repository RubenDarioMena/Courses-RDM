Transiciones y animaciones

Las transiciones dan un puente suave entre dos estados. Las animaciones son coreografías completas: definís un principio, un final y el navegador se encarga del viaje. Bien usadas, convierten una página en una experiencia.

Sin instalar nada Pruébalo en el editor ~12 min de lectura
iLa idea en una imagen

Pensalo así: una transición es un puente que se levanta cuando pasás de A a B. Una animación es una coreografía con varios pasos. Y en ambos casos, el motor gráfico (GPU) puede ayudarte si elegís bien qué propiedades mover.

Transición
:hover { transform: scale(1.05) }
Disparada por un cambio de estado. Dos puntos: inicio y fin. Interpolación suave entre ambos.
Animación
@keyframes spin { to { transform: rotate(360deg) } }
Definís una coreografía completa. Puede repetirse, pausarse o cambiar de dirección.
Rendimiento
opacity · transform
Solo estas dos propiedades se aceleran por GPU. Animá width/height y verás parpadeo.
01transition: el puente entre dos estados

Una transición se aplica a una propiedad y se dispara cuando esa propiedad cambia (por un :hover, una clase, un cambio de tema, etc.). La propiedad transition es un atajo de cuatro:

CSS 
.btn {
  background: #10B981;
  color: #fff;
  padding: 12px 22px;
  border-radius: 10px;
  /* transition: <property> <duration> <timing-function> <delay> */
  transition: background 0.25s ease,
              transform 0.2s cubic-bezier(0.4, 0, 0.2, 1);
}
.btn: hover {
  background: #34D399;
  transform: scale(1.05);
}

Las cuatro partes del atajo

La forma larga separa las cuatro piezas. Si una propiedad no está en transition-property, el cambio es instantáneo. all es cómodo pero peligroso, porque algunas propiedades (como width) son lentas de animar.

CSS 
transition-property:        transform, background;
transition-duration:        0.2s, 0.25s;
transition-timing-function: ease, cubic-bezier(0.4, 0, 0.2, 1);
transition-delay:           0s, 0.05s;
02@keyframes: coreografías completas

Las animaciones son para cuando necesitás más de dos estados o querés que la cosa se repita sola. Definís la coreografía con @keyframes y la activás con la propiedad animation.

CSS 
/* 1) la coreografía */
@keyframes spin {
  from { transform: rotate(0deg); }
  to   { transform: rotate(360deg); }
}

/* 2) la activación sobre un elemento */
.spinner {
  width: 32px;
  height: 32px;
  border: 3px solid rgba(52, 211, 153, 0.2);
  border-top-color: #34D399;
  border-radius: 50%;
  animation: spin 1s linear infinite;
}

Propiedades del atajo animation

Orden canónico: name duration timing-function delay iteration-count direction fill-mode play-state. Las más usadas en la práctica:

CSS 
animation-name:          spin;
animation-duration:      1s;
animation-iteration-count: infinite;       /* o un número entero */
animation-direction:     normal | reverse | alternate | alternate-reverse;
animation-fill-mode:     none | forwards | backwards | both;

alternate hace que la animación vaya y vuelva de forma continua (un péndulo, una respiración). forwards deja al elemento en el estado final — clave cuando animás "algo que entra".

Curvas de timing: ease, cubic-bezier(), steps()

La curva define el ritmo del cambio, no su velocidad total:

CSS 
transition-timing-function: ease;                       /* default — arranque y fin suaves */
transition-timing-function: linear;                     /* velocidad constante              */
transition-timing-function: cubic-bezier(0.4, 0, 0.2, 1); /* curva "estándar" de Material     */
transition-timing-function: steps(8, end);               /* saltos discretos (sprite sheets) */

steps() es el secreto de los spinners de "tic-tac" y de los sprites animados: en vez de interpolar, da saltos discretos. cubic-bezier(0.4, 0, 0.2, 1) es la curva de Material Design y se siente natural en casi cualquier UI.

03Performance y accesibilidad de movimiento

El navegador repinta la página en cada frame. Algunas propiedades son baratas de mover (la GPU las maneja en una capa aparte). Otras son caras (recalculan layout o repintan píxeles). Animar las baratas se siente como seda; animar las caras produce jank y parpadeo.

🟢 Animá tranquilo (GPU)
opacity · transform
No producen layout ni repaint. El navegador sube el elemento a una capa en GPU y lo mueve entero.
🔴 Evitá animar
width · height · top · left
Disparan layout en cada frame. Una animación de 60fps se vuelve un arrastre. Usá transform en su lugar.
🟡 Con cuidado
background · color · box-shadow
No producen layout pero sí repaint. Para cambios cortos o sutiles andan bien; evitá animaciones largas.

Respetá al usuario: prefers-reduced-motion

Hay personas con desordenes vestibulares para las que una animación de medio segundo puede ser un problema serio. El sistema operativo expone una preferencia que CSS puede leer:

CSS 
.spinner { animation: spin 1s linear infinite; }
.btn     { transition: transform 0.2s ease; }

@media (prefers-reduced-motion: reduce) {
  .spinner { animation: none; }
  .btn     { transition-duration: 0.01ms; }
}

Si la persona activa "reducir movimiento" en su sistema, tus animaciones se apagan o se vuelven instantáneas. Un detalle pequeño que marca una diferencia enorme.

3 detalles que valen oro

1

Listá las propiedades explícitamente

transition: transform 0.2s, background 0.25s es mejor que transition: all 0.3s — no animás por accidente algo caro.

2

transform > width/height

Para "agrandar" usá transform: scale(). Para "mover" usá translate. Nunca width, height, top o left en animaciones largas.

3

prefers-reduced-motion, siempre

Una sola media query corta toda animación. Seis líneas que respetan a personas con sensibilidad vestibular. Cero costo, todos los beneficios.
