Flujo y posicionamiento

Los elementos en CSS viven en un flujo: una corriente que los coloca uno tras otro. Pero a veces necesitas sacarlos de ahí — fijarlos arriba, superponerlos, mandarlos al fondo. Aquí ves cómo tomar ese control sin pelearte con la maquetación.

block vs inline 5 valores de position ~12 min de lectura
1El flujo normal: block, inline e inline-block

Tres comportamientos, tres misiones

Por defecto, cada elemento tiene un display que decide cómo se coloca en la página. Lo entiendes en 30 segundos con esta tabla mental:

block
Ocupa todo el ancho. Comienza en nueva línea. Acepta width, height, margin vertical. Ej: div, p, h1.
inline
Solo ocupa su contenido. No fuerza salto de línea. No acepta width/height ni margin vertical. Ej: span, a, strong.
inline-block
Como inline (sigue el flujo) pero acepta width, height y margin en los 4 lados. Ideal para botones, badges, iconos.
.badge {
  display: inline-block;
  padding: 4px 10px;
  background: #34D399;
}
2position: los 5 valores que te sacan del flujo

La propiedad position cambia la relación del elemento con el flujo y con sus padres. Los cinco valores, de menos a más intervención:

static
El valor por defecto. Sigue el flujo normal. Ignora top/right/bottom/left.
relative
Permite desplazar con top/left etc. Sin sacar del flujo — su hueco se reserva.
absolute
Saca del flujo. Se posiciona respecto al ancestro posicionado más cercano (no static).
fixed
Saca del flujo y se pega a la ventana del navegador. No se mueve al hacer scroll.
sticky
Híbrido: relative hasta que el scroll lo activa, y entonces se vuelve fixed dentro de su contenedor.
.navbar { position: fixed; top: 0; left: 0; right: 0; z-index: 30; }
.badge  { position: absolute; top: 8px; right: 8px; }
.seccion-h2 { position: sticky; top: 0; }

z-index y contextos de apilamiento

z-index decide qué elemento va delante cuando se superponen. Solo funciona con elementos posicionados (no static) o con flex/grid items. Un elemento con z-index crea un contexto de apilamiento: sus hijos se apilan entre sí, no con el resto.

Regla práctica: navbar arriba (z grande), modales aún más arriba (z más grande), y nunca uses valores absurdos como 9999 — usa una escala de 10, 20, 30, 100.

float y clear (histórico, aún aparece en código viejo)

Antes de flexbox, float era la única forma de poner elementos uno al lado del otro. Hoy se evita para layout, pero sigue vivo para cosas como imagen con texto alrededor. Si ves float: left en código moderno, casi siempre hay una forma mejor con flex o grid.

img.avatar { float: left; margin-right: 12px; }
.clearfix::after { content: ""; display: block; clear: both; }
3Tu primer momento: navbar fixed + hero con overlay

Esta preview es una composición real: una navbar fija en la parte superior, y debajo un hero con un degradado y un overlay oscuro que mejora la legibilidad del texto. Es el patrón más usado en landings y portfolio.

3 trucos de posicionamiento profesionales

1

Añade padding-top al body

Una navbar fixed sale del flujo. Compensa con padding-top en body igual a la altura de la navbar, o el contenido inicial quedará oculto.

2

Usa inset: 0 en lugar de top/right/bottom/left

El shorthand inset: 0 equivale a poner los cuatro lados a 0. Más limpio para overlays y elementos que cubren todo el padre.

3

Reserva z-index en decenas

Usa 10, 20, 30, 40... así siempre puedes intercalar un valor entre dos existentes sin renumerar todo.
