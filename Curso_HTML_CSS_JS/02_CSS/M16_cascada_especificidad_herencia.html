MÓDULO 16 · CASCADA

Cascada, especificidad y herencia

Cuando dos reglas quieren pintar el mismo elemento, ¿quién gana? CSS tiene un sistema claro para decidirlo: la cascada. Aquí aprendes las tres reglas que siempre mandan — origen, especificidad y orden de aparición — y cómo controlarlas.

3 reglas para desempatar Tres reglas compiten a la vez ~12 min de lectura
1La cascada: el orden de las prioridades

¿Qué pasa cuando dos reglas dicen cosas distintas?

CSS significa Cascading Style Sheets: "hojas de estilo en cascada". La cascada es el algoritmo que decide qué estilo gana cuando varias reglas compiten por el mismo elemento. Hay tres niveles en este orden estricto:

1. Origen e importancia

De menor a mayor prioridad: estilos del navegador (user-agent), luego estilos del autor (tu CSS), y por encima los del usuario (accesibilidad). !important rompe ese orden y siempre gana — pero úsalo con cabeza, es una bomba atómica.

/* !important gana sobre TODO (incluso inline) */
.boton { background: tomato !important; }
#boton { background: royalblue; }      /* esta pierde */

2. Especificidad

Si ambas reglas son del autor y no hay !important, gana la más específica (la siguiente sección).

3. Orden de aparición

Si empatan en especificidad, gana la regla que aparece más tarde en el CSS. Por eso el orden importa.

p { color: tomato; }
p { color: royalblue; }   /* esta gana: aparece después */
2La especificidad: ID > clase > tipo

Cada selector tiene un peso que se calcula con tres dígitos: (ID, clase, tipo). A más dígitos y más a la izquierda, más fuerte.

SelectorEspecificidadSignificado

.caja0,1,0una clase
#caja1,0,0un ID
div.caja0,1,1tipo + clase

style="..."1,0,0,0inline: siempre 1.0.0.0
 
/*  Compiten por el color del párrafo:        */
p            { color: tomato; }        /* 0,0,1  → pierde */
.texto       { color: orange; }      /* 0,1,0  → gana sobre p  */
#caja .texto { color: green; }       /* 1,1,0  → gana sobre todas */

Regla práctica: evita IDs para estilo (mejor class), mantén los selectores cortos y no compitas con !important.

3Herencia: lo que se transmite a los hijos

Qué se hereda y qué no

Algunas propiedades se transmiten de padres a hijos (color, font-family, line-height, text-align). Otras no (margin, border, padding, width, height). Si un hijo no tiene su propia regla, hereda el valor del padre.

body { color: #EEEBF6; font-family: system-ui; }
/* todos los textos heredan color y font, pero no margin */

Forzar la herencia: inherit / initial / unset / revert

Estas cuatro palabras clave te dan control total sobre la herencia cuando algo no sale como esperas.

a     { color: inherit; }   /* hereda el color del padre */
.reset { all: initial; }  /* vuelve al valor inicial de la propiedad */
.natural { color: unset; } /* inherit si se hereda, initial si no */
.nav-link { all: revert; } /* vuelve al estilo del navegador */

Cascade layers (@layer)

Es la forma moderna de controlar la prioridad sin !important. Declaras capas y el orden en que aparecen define la prioridad: la última capa declarada tiene más peso.

@layer reset, base, components, utilities;

@layer base {
  button { background: gray; }
}
@layer utilities {
  .btn-primario { background: #34D399; }  /* gana */
}

Las capas ignoran la especificidad dentro de cada capa, así puedes controlar el orden global con una sola declaración arriba del CSS.

4Tu primer momento: tres reglas compiten

Este cuadro tiene tres reglas compitiendo: un selector de tipo, uno de clase y un ID. Por defecto gana el más específico (el ID). Pulsa el botón para activar !important en la regla más débil y verás cómo cambia el resultado al instante.

CSS — cascada en vivo 
/* Tres reglas compiten por el mismo color: */

¿Y ahora qué? Tres pasos para entrenar el ojo

1

Predice antes de mirar

Lee las reglas, calcula la especificidad (ID, clase, tipo) y di en voz alta quién gana. Luego ejecuta y comprueba.

2

Rompe el orden con !important

Pulsa el botón de la preview. Ahora un selector de tipo (el más débil) supera al ID solo por llevar !important.

3

Inspecciona con DevTools

Abre el playground, escribe 5 reglas para un mismo elemento y mira la pestaña Computed: verás cuál se aplica y cuáles aparecen tachadas.
