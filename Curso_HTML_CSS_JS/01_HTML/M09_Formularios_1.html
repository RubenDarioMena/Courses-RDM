Formularios (parte 1)

Hasta ahora el usuario solo leía. Con los formularios puede escribir, elegir y enviar datos. Aquí verás la etiqueta <form>, los tipos de <input>, los campos de texto largo, los selectores, los botones y cómo activar la validación nativa del navegador sin escribir una sola línea de JavaScript.

<form> con action y method Validación nativa (sin JS) ~90 min de lectura
1 <form> · action y method

Un formulario es un envoltorio que agrupa campos y se encarga de enviarlos a algún sitio. Sin <form>, los inputs se ven pero no se envían a nada. Sus dos atributos esenciales son action (a dónde van los datos) y method (cómo viajan).

HTML · esqueleto de un formulario 
<!-- action = URL que recibe los datos
     method = cómo viajan: GET (en la URL) o POST (en el cuerpo) -->
<form action="/registro" method="post">
  <!-- aquí van los campos -->
  <button type="submit">Enviar</button>
</form>

GET vs POST, en una frase cada uno

GET — los datos se ven en la URL. Úsalo para búsquedas y filtros (compartibles, cacheables, no sensibles). POST — los datos van en el cuerpo de la petición. Úsalo para registros, login, pagos, subida de archivos. Nunca envíes contraseñas con GET.

GET
?nombre=Ana&edad=30
Datos en la URL. Visible en el historial y al compartir el enlace. Limitado a ~2000 caracteres.
POST
cuerpo de la petición
Datos ocultos en el cuerpo. Sin límite práctico. Obligatorio para datos sensibles o archivos.
enctype
multipart/form-data
Atributo extra necesario si subes archivos. Para texto normal basta con el valor por defecto.
2 Tipos de <input> (texto y números)

El elemento <input> es un vacío (no tiene cierre) y cambia radicalmente su comportamiento según el atributo type. Aquí los cinco tipos que cubren el 80% de los formularios de texto y datos.

HTML · inputs de texto y números 
<label for="nombre">Nombre</label>
<input id="nombre" type="text" name="nombre" required minlength="2">

<label for="email">Email</label>
<input id="email" type="email" name="email" required>

<label for="password">Contraseña</label>
<input id="password" type="password" name="password" minlength="8">

<label for="edad">Edad</label>
<input id="edad" type="number" name="edad" min="18" max="99">

<label for="nacimiento">Fecha de nacimiento</label>
<input id="nacimiento" type="date" name="nacimiento">

Qué hace cada type por ti

text: caja libre. email: en móvil aparece el teclado con @; en escritorio valida el formato al enviar. password: oculta lo escrito y desactiva el autocompletar visible. number: solo números, con flechas y validación de rango. date: abre un calendario nativo del sistema operativo.

El atributo name es el que forma el par clave=valor que se envía. Sin name, el campo no se envía aunque esté relleno.

3 Label, textarea, select, button

Además de los <input> cortos, hay cuatro elementos que necesitas para casi cualquier formulario real. El <label> es obligatorio por accesibilidad y el resto cubren los huecos que los inputs cortos no resuelven.

HTML · label, textarea, select, button 
<!-- label asociado por id (clic en el texto enfoca el input) -->
<label for="bio">Cuéntanos sobre ti</label>
<textarea id="bio" name="bio" rows="4" maxlength="200"></textarea>

<!-- select: lista desplegable. La opción "vacía" obliga a elegir -->
<label for="pais">País</label>
<select id="pais" name="pais" required>
  <option value="">— elige uno —</option>
  <option value="es">España</option>
  <option value="mx">México</option>
  <option value="ar">Argentina</option>
</select>

<!-- button type=submit envía el formulario. type=reset lo limpia. -->
<button type="submit">Registrar</button>
<button type="reset">Limpiar</button>

La regla de oro de <label>

El atributo for del <label> debe coincidir con el id del campo. Así, al hacer clic en el texto, el cursor salta al input, y los lectores de pantalla anuncian el campo correctamente. Si los ids no coinciden, el formulario "sigue funcionando", pero pierdes usabilidad y accesibilidad.

El <textarea> lleva contenido de cierre, no es void. Su tamaño se controla con rows y cols, pero lo habitual es dejarlo en CSS. El <select> siempre debe tener al menos un <option>; si quieres un "placeholder", añade una opción con value="" como la del ejemplo.

4 Validación nativa del navegador

El navegador ya sabe validar formularios. Con solo añadir atributos, bloquea el envío y muestra mensajes contextuales. No necesitas JavaScript para el 90% de los casos. Estos son los cinco atributos de validación que más vas a usar.

required
required
El campo no puede estar vacío. Funciona con text, email, password, checkbox, radio, select, textarea, date, number.
pattern
pattern="(?=.*\d).{8,}"
Expresión regular que el valor debe cumplir. Útil para contraseñas, códigos postales, prefijos. Usa anclas implícitas.
min / max
min="18" max="99"
Rango numérico o fecha mínima/máxima. Con type="number" valida números; con type="date", fechas.
minlength / maxlength
minlength="2" maxlength="200"
Longitud mínima y máxima de caracteres. En textarea maxlength además impide escribir más allá del límite.
type
type="email"
El propio type ya valida: email, url, number, date, tel, time. No hay que añadir nada más.
HTML · ejemplo combinado 
<label for="pass">Contraseña (8+, 1 mayúscula, 1 dígito)</label>
<input id="pass"
       type="password"
       name="password"
       minlength="8"
       pattern="(?=.*\d)(?=.*[A-Z]).{8,}"
       required>

¿Quieres cambiar el mensaje que muestra el navegador? Más adelante (en el bloque de JavaScript) veremos setCustomValidity(). Por ahora, los mensajes en español del navegador son perfectamente válidos.

5 Checkbox, radio, fieldset y legend

Para elegir entre opciones hay dos tipos: checkbox (varias a la vez) y radio (solo una de un grupo). Para agruparlos visual y semánticamente, se envuelven en <fieldset> con un <legend> como título del grupo.

HTML · agrupación con fieldset y legend 
<!-- Grupo de radios: comparten el mismo "name" → solo se puede elegir uno -->
<fieldset>
  <legend>Tipo de cuenta</legend>

  <label>
    <input type="radio" name="cuenta" value="personal" required>
    Personal
  </label>

  <label>
    <input type="radio" name="cuenta" value="empresa">
    Empresa
  </label>
</fieldset>

<!-- Checkbox independiente: marca de aceptación -->
<label>
  <input type="checkbox" name="terminos" required>
  He leído y acepto los términos
</label>

Dos formas válidas de asociar label e input

Por atributo for — el <label> y el <input> están separados, y el for apunta al id. Útil cuando el label va antes y necesitas estructura limpia.

Anidando el input dentro del label — el <label> envuelve al <input> (como en el ejemplo de los radios). Más compacto y perfecto para radios y checkboxes cortos.

Por qué importa <fieldset>

Visualmente dibuja un borde alrededor del grupo. Semánticamente, comunica a los lectores de pantalla "estos campos van juntos". El <legend> actúa como el título de ese grupo, igual que un <h3> pero dentro de un formulario.
