MÓDULO 11 · ACCESIBILIDAD (A11Y)

Haz tu web para todos

Una web que solo funciona con ratón deja fuera a millones de personas. Aquí aprendes el HTML semántico que el lector de pantalla entiende, el orden de teclado que respeta la lógica, ARIA cuando lo nativo no basta, y a auditar todo con Lighthouse. La accesibilidad no es un extra: es la base.

HTML semántico + ARIA Auditoría con Lighthouse ~75 min de lectura

Nota: La pestaña "Red" de DevTools se cubre de forma conceptual en este módulo — el curso no usa red real.

1 HTML semántico como base

La accesibilidad empieza antes que ARIA: empieza por elegir la etiqueta correcta. Un <button> ya es focuseable,.envía el formulario y anuncia "botón" al lector de pantalla sin que tú hagas nada. Si usas <div onclick>, rompes las tres.

Roles landmark implícitos

Cada elemento semántico expone un rol ARIA automáticamente al navegador. Esto es lo que el lector de pantalla anuncia al entrar en cada zona:

HTML · landmarks 
<header>   <!-- role=banner -->
<nav>      <!-- role=navigation -->
<main>     <!-- role=main -->
<aside>    <!-- role=complementary -->
<footer>   <!-- role=contentinfo -->
<form>    <!-- role=form -->
<search>   <!-- role=search -->

✓ Haz

<button>Guardar cambios</button> <a href="/login">Entrar</a>

✗ No hagas

<div onclick="save()">Guardar</div> <span onclick="login()">Entrar</span>
2 tabindex y navegación por teclado

El teclado es el primer input accesible. Pulsa Tab y el foco recorre los controles interactivos en orden lógico (el del DOM). Tu trabajo: no romper ese orden.

Los tres valores de tabindex

HTML · tabindex 
<!-- Sin tabindex: el navegador decide el orden -->
<button>Guardar</button>

<!-- tabindex="0": focuseable, orden natural del DOM -->
<div tabindex="0">...</div>

<!-- tabindex="-1": focuseable por JS, no con Tab -->
<div tabindex="-1">...</div>

<!-- tabindex="3": EVÍTALO. Salta el orden natural -->
<!--Solo genera caos. Casi nunca se necesita. -->

Foco visible

El navegador dibuja un outline en el elemento con foco. Si tu CSS lo quita, estás cegando a quien navega con teclado. Refuérzalo en su lugar:

CSS · focus-visible 
:focus-visible {
  outline: 3px solid #A78BFA;
  outline-offset: 2px;
}
3 ARIA: cuando lo nativo no basta

La regla nº1 de ARIA es: no uses ARIA si un elemento HTML nativo ya hace el trabajo. ARIA se reserva para patrones que HTML no cubre (tabs custom, live regions, árboles expandibles). Los atributos que verás en este módulo:

HTML · ARIA 
<nav aria-label="Principal">...</nav>       <!-- etiqueta la zona -->
<section aria-labelledby="tit">                    <!-- referencia por id -->
  <h2 id="tit">Noticias</h2>...</section>
<input aria-describedby="ayu">             <!-- pista extra asociada -->
<p id="ayu">8 caracteres mínimo</p>
<div role="status" aria-live="polite"></div>  <!-- live region -->

✓ aria-label

<button aria-label="Cerrar">✕</button>

✗ Sin etiqueta

<button>✕</button>
4 alt correcto: decorativa vs informativa

El alt decide qué oye el lector de pantalla cuando pasa por una imagen. Hay dos casos, y se resuelven de forma opuesta.

✓ Imagen informativa

<img src="grafico.jpg" alt="Ventas 2025: subida del 30 % en Q3">

El alt describe lo que la imagen transmite, no lo que es.

✓ Imagen decorativa

<img src="ondas.svg" alt="">

alt vacío: el lector la ignora. La pantalla ya la ve.

✗ El error clásico

<img src="logo.png" alt="imagen">

"imagen" no ayuda a nadie. Si la imagen es decorativa, alt vacío. Si comunica algo, descríbelo.

5 Ejercicio: auditar con Lighthouse y corregir

Vas a construir a propósito una página con fallos, auditarla, corregir los tres peores y volver a lanzar Lighthouse para ver la puntuación subir.

1

Crea a11y-audit.html

Header sin nav, 2 imágenes sin alt, un botón "Clic aquí" no descriptivo y un <div onclick> sin rol ni tabindex.

2

Abre DevTools → Lighthouse

Lanza auditoría de Accessibility (puedes desmarcar SEO y Rendimiento). Revisa los fallos listados.

3

Corrige 3 problemas

alt="" a la decorativa y alt descriptivo a la informativa. Cambia "Clic aquí" por "Guardar cambios". Sustituye el <div onclick> por un <button> nativo (o añade role="button" tabindex="0").

4

Vuelve a lanzar Lighthouse

Compara las puntuaciones. Revisa también la pestaña "Issues" o "Accessibility" de DevTools.

5

Prueba el teclado

Sin ratón, pulsa Tab repetidamente: el foco debe recorrer todos los controles en orden lógico y visible. Añade :focus-visible si no se distingue.
