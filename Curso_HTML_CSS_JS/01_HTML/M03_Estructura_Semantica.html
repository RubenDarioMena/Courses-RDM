MÓDULO 03 · ESTRUCTURA SEMÁNTICA

Dale a tu web significado

Un div no dice nada. Un header, un nav o un article cuentan al navegador, a los buscadores y a los lectores de pantalla qué papel juega cada bloque. En este módulo aprenderás a estructurar una página con etiquetas que describen el contenido, no solo lo envuelven.

HTML semántico Runner en vivo ~75 min de lectura
1 Los siete elementos semánticos

HTML5 introdujo un puñado de etiquetas que describen las partes comunes de cualquier página. No cambian el aspecto visual (eso es trabajo del CSS), pero sí le dicen al navegador y a las máquinas qué es cada bloque. Memoriza este mapa: describe el 90 % de las webs modernas.

HTML · mapa semántico 
<body>
  <header>   <!-- logo, título, intro de la página o sección -->
    <nav>         <!-- men\u00fa principal de navegaci\u00f3n -->
      <a href="/">Inicio</a>
      <a href="/blog">Blog</a>
    </nav>
  </header>

  <main>      <!-- contenido central y \u00fanico de la p\u00e1gina -->
    <article>   <!-- contenido aut\u00f3nomo: un post, una noticia... -->
      <h2>T\u00edtulo del post</h2>
      <p>Contenido...</p>
    </article>
    <aside>    <!-- contenido relacionado: sidebar, publicidad... -->
      <h3>Enlaces</h3>
      <ul><li>...</li></ul>
    </aside>
  </main>

  <footer>   <!-- info de cierre: copyright, autor, enlaces... -->
    <p>© 2026 Mi Blog</p>
  </footer>
</body>

Siete etiquetas, siete roles

  • <header> — cabecera de página o de sección (logo, título, intro)
  • <nav> — menú de navegación principal o secundario
  • <main> — el contenido central y único de la página (uno solo por documento)
  • <article> — contenido autónomo que podría vivir solo (un post, una noticia)
  • <section> — agrupación temática de contenido con su propio encabezado
  • <aside> — contenido relacionado, tangencial al principal (sidebar,_related)
  • <footer> — pie de la página o de una sección (copyright, contacto, enlaces)
2 <div> vs <section> vs <article>

Las tres etiquetas sirven para agrupar, pero su intención es diferente. Elegir bien comunica significado a buscadores y lectores de pantalla; elegir mal lo confunde. Esta es la regla que casi nadie explica bien.

1

<article> — contenido autónomo

¿Podrías copiar este bloque, pegarlo en otro sitio y seguiría teniendo sentido por sí solo? Si la respuesta es sí, es un article. Ejemplos: un post de blog, una noticia, un comentario, un producto en una lista.

2

<section> — agrupación temática

¿Tiene sentido como unidad y lleva un encabezado propio (h2, h3…)? Si la respuesta es sí, es una section. Ejemplos: "Capítulos", "Comentarios", "Sección de contacto".

3

<div> — agrupación neutra

¿No tiene significado semántico, solo sirve para CSS o layout? Si la respuesta es sí, usa div. Es la caja genérica. No la uses si una etiqueta semántica describe mejor el contenido.

Pueden anidarse. Un <article> puede contener varios <section>; una página puede tener varios <article> dentro de un <main>. La clave es siempre preguntarte: ¿este bloque es autónomo, temático o neutro?

3 Enlazando CSS y JavaScript externos

El HTML es el esqueleto. El CSS es la piel. El JavaScript es el sistema nervioso. Para que se unan, el HTML los enlaza en el head — con dos etiquetas muy distintas.

CSS — <link rel="stylesheet">

Es un void element. No lleva cierre. Apunta a un archivo CSS externo con el atributo href.

HTML · enlazar CSS 
<link rel="stylesheet" href="styles.css">

JavaScript — <script src defer>

El navegador lee el HTML de arriba abajo. Si encuentra un <script> sin más, se detiene a descargarlo y ejecutarlo antes de seguir. Eso ralentiza la página. La solución mágica es el atributo defer.

HTML · enlazar JS con defer 
<!-- defer: descarga el JS en paralelo, pero lo ejecuta DESPUÉS del HTML -->
<script src="script.js" defer></script>

<!-- sin defer: el navegador se para hasta que el JS se ejecute. MAL. -->
<script src="lento.js"></script>

Por qué defer te va a ahorrar dolores de cabeza

Sin defer, si tu JS intenta seleccionar un elemento del DOM que aún no existe, falla. Con defer, el JavaScript se ejecuta cuando el HTML ya está completo, así que todo el DOM está disponible. Tu vida como desarrollador acaba de mejorar.

4 Tu ejercicio: estructura un blog

Vas a construir el esqueleto de un blog completo. Un header con título y navegación, un main con dos article, un aside con enlaces y un footer global.

1

Crea blog.html con la estructura mínima

<!DOCTYPE html>, <html lang="es">, <head> con charset y viewport, y <body> vacío.

2

Añade el <header> con un <nav>

Dentro del header: un <h1> con el nombre del blog, y una <nav> con 3 enlaces ("Inicio", "Artículos", "Contacto").

3

Inserta el <main> con dos <article>

Cada article: un <h2> con el título del post, un <p> con el contenido y un <footer> con la fecha (texto plano por ahora).

4

Añade un <aside> con enlaces recomendados

Una <ul> con tres <li> y dentro de cada uno un <a href="#">. Puede ir dentro del main o antes del footer.

5

Cierra con un <footer> global

Incluye un <p> con tu nombre y el año. Enlaza un CSS ficticio y un JS con defer: <link rel="stylesheet" href="styles.css"> y <script src="script.js" defer></script>. Abre DevTools y verifica el árbol semántico.

5 Pruébalo aquí mismo

Pulsa Ejecutar para ver renderizado el esqueleto semántico de un blog. Observa cómo header, nav, main, article, aside y footer se apilan por su contenido, sin un solo div.
