1 Validación W3C

El validador de la W3C (validator.w3.org) lee tu HTML y lista cada etiqueta mal cerrada, cada atributo mal escrito, cada anidamiento imposible. Es el lint del HTML: pásalo antes de entregar cualquier página.

Los tres errores más comunes

HTML · errores típicos 
<!-- 1. Etiqueta sin cerrar -->
<p>Hola <!-- falta </p> -->

<!-- 2. Anidamiento imposible -->
<a href="#"><button>...</button></a>   <!-- un botón NO puede vivir dentro de un enlace -->

<!-- 3. Atributo duplicado o no permitido -->
<img src="a.jpg" src="b.jpg">           <!-- src dos veces -->

Pega la URL de tu página (o sube el archivo) en validator.w3.org y corrige hasta que el informe diga "Document checking completed. No errors or warnings".

2 Separación de capas

La regla de oro del frontend moderno: HTML estructura, CSS estila, JS comporta. Cada capa tiene un trabajo y no debe hacer el de la otra. Mezclarlas genera código que no se mantiene.

HTML · estructura

El esqueleto semántico: qué es cada cosa (un botón, un artículo, un nav).

CSS · estilo

Cómo se ve: color, tamaño, posición, animación. Vive en su archivo .css.

JS · comportamiento

Qué hace al interactuar: listeners, lógica, peticiones. Vive en su .js.

HTML · mala vs buena práctica 
<!-- ✗ Mezclar estilos y comportamiento en el HTML -->
<div style="color:red" onclick="alert('hola')">Saludar</div>

<!-- ✓ Cada capa en su sitio -->
<button class="btn-saludar">Saludar</button>
<!-- CSS: .btn-saludar{color:red}  ·  JS: addEventListener('click', ...) -->
3 defer para scripts, lazy para imágenes

Dos atributos que mejoran el rendimiento sin tocar tu lógica: defer en los <script> y loading="lazy" en las imágenes no críticas.

1

defer en todos los <script>

El navegador descarga el script en paralelo sin bloquear el render del HTML y lo ejecuta al parsear la página. Sin defer, el script pausa el pintado.

2

loading="lazy" en imágenes no críticas

Las imágenes fuera de la ventana visible se cargan solo cuando el usuario hace scroll hacia ellas. Ahorra ancho de banda y acelera el primer render.

HTML · defer + lazy 
<!-- Script sin bloquear -->
<script src="app.js" defer></script>

<!-- Imagen diferida -->
<img src="hero.jpg" alt="..." width="640" height="360">
<img src="galeria/06.jpg" alt="..." width="400" height="300" loading="lazy">

DevTools: revisa páginas con el Inspector, la pestaña Accesibilidad y la pestaña Red (conceptual — el curso no usa red real).

4 Proyecto final del bloque HTML

Construye una página web completa (tema: portfolio personal o negocio local) que cumpla los cinco requisitos siguientes. Es la culminación de todos los módulos anteriores en un solo archivo.

1

Estructura semántica completa

<header> con <nav>, <main> con 2 <section> + 1 <aside>, <footer> con <address>. Usa <article> para entradas. Un único <h1> y jerarquía <h2>–<h3> correcta.

2

Imágenes accesibles

Mínimo 3 <img> con alt informativo, width/height explícitos y loading="lazy". Usa <figure> + <figcaption> en al menos una.

3

Tabla de productos/servicios

Un <table> con <caption>, <thead>, <tbody>, <tfoot>, <th scope> y un <td colspan> o rowspan.

4

Formulario de contacto

<form> con <label> por cada campo, tipos variados (text, email, tel, <select>, <textarea>), <fieldset>/<legend> y validación nativa (required, pattern, minlength). Incluye <button type="submit">.

5

Metadatos SEO y social

<title>, <meta name="description">, Open Graph completo (og:title, og:description, og:image), Twitter Card, <link rel="canonical">, JSON-LD con @type adecuado (p.ej. LocalBusiness o Person), favicon y <meta name="theme-color" content="#A78BFA">.
