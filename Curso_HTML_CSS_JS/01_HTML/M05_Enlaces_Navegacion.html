MÓDULO 05 · ENLACES Y NAVEGACIÓN

La etiqueta que inventó la web

Un documento sin enlaces es solo papel. El elemento <a> convirtió documentos sueltos en una red: navegación interna, enlaces externos, correos, llamadas y descargas. En este módulo aprendes a dominarlo todo — incluido el detalle de seguridad que casi nadie explica y que te puede salvar de un ataque.

href, target, rel Runner en vivo ~60 min de lectura
1 La anatomía de <a href>

El enlace es el elemento más poderoso de la web. Lo aprendes en cinco segundos y lo perfeccionas en cinco años. Todo empieza por su atributo estrella: href — hypertext reference, la dirección de destino.

HTML · anatomía del enlace 
<a href="https://developer.mozilla.org">
  Documentación MDN              <!-- el texto visible que se clica -->
</a>
   ↑                              ↑
   href = destino (URL)            contenido = lo que ve el usuario

Las dos caras del enlace: absoluto vs relativo

El href puede apuntar a otra web (URL absoluta) o a una página dentro de tu propio sitio (URL relativa). Saber cuándo usar cada una es lo que diferencia tu sitio sano de un sitio con enlaces rotos.

HTML · absoluto vs relativo 
<!-- Absoluto: protocolo + dominio completo -->
<a href="https://developer.mozilla.org">MDN</a>

<!-- Relativo: ruta dentro de tu propio sitio -->
<a href="blog.html">Blog</a>
<a href="posts/pan.html">Pan</a>
<a href="../contacto.html">Contacto</a>   <!-- sube un nivel -->
<a href="/">Inicio</a>                 <!-- raíz del sitio -->

Si tu sitio cambia de dominio, los enlaces relativos siguen funcionando: solo cambian de contexto. Los absolutos apuntan siempre al mismo destino, vayas donde vayas. Por eso, enlaces internos — relativos; enlaces a otros sitios — absolutos.

2 Anclas: navegación interna

¿Quieres que al pulsar un enlace el navegador salte a una sección de la misma página? Para eso existen las anclas: enlaces que apuntan a un id del documento mediante el símbolo #.

HTML · anclas con #id 
<!-- Índice de navegación interna -->
<nav>
  <ul>
    <li><a href="#seccion-1">Introducción</a></li>
    <li><a href="#seccion-2">Desarrollo</a></li>
    <li><a href="#seccion-3">Conclusión</a></li>
  </ul>
</nav>

<!-- El destino: cualquier etiqueta con ese id -->
<section id="seccion-1">
  <h2>Introducción</h2>
  <p>Bienvenido a este artículo...</p>
</section>

Reglas de las anclas

  • El href usa # + el valor exacto del id de destino.
  • Los id son únicos en la página: si se repiten, el navegador solo salta al primero.
  • Puedes enlazar a una sección de otra página: <a href="blog.html#pan">.
3 target="_blank" y rel: la pareja inseparable

Hay una pareja de atributos que siempre van juntos cuando abres un enlace en una pestaña nueva. Olvidar el segundo es uno de los errores de seguridad más comunes en HTML. Vamos a ver por qué.

target="_blank" — abre en una pestaña nueva

El atributo target dice dónde se abre el enlace. El valor _blank significa "una pestaña nueva o ventana nueva". El usuario no abandona tu página.

rel="noopener noreferrer" — el guardaespaldas

Sin rel="noopener noreferrer", la página nueva puede acceder al objeto window.opener de tu página original. Una página maliciosa podría, en algunos navegadores antiguos, redirigir tu pestaña a una web de phishing sin que el usuario lo note. Siempre acompaña target="_blank" con este rel.

HTML · enlace externo seguro 
<!-- CORRECTO: target + rel juntos. Siempre. -->
<a href="https://developer.mozilla.org"
   target="_blank"
   rel="noopener noreferrer">
  Documentación MDN
</a>

<!-- MAL: target sin rel. Riesgo de seguridad. -->
<a href="externo.html" target="_blank">Peligroso</a>

¿Qué hace cada valor de rel?

  • noopener — la página nueva no puede acceder a window.opener de tu página.
  • noreferrer — no envía la URL de origen al sitio de destino (extra de privacidad).
  • nofollow — le dices a los buscadores: "no sigas este enlace" (útil para enlaces patrocinados).
4 Esquemas especiales: mailto, tel, download

El atributo href no solo apunta a URLs http. Hay esquemas especiales que disparan otras apps del sistema — el correo, el teléfono, o una descarga directa. Conocerlos te ahorra componentes de JavaScript enteros.

Los cuatro esquemas que más usarás

HTML · esquemas especiales 
<!-- Mailto: abre la app de correo con destinatario precargado -->
<a href="mailto:tucorreo@ejemplo.com">Escríbeme</a>

<!-- Mailto con asunto y cuerpo del mensaje -->
<a href="mailto:hola@ejemplo.com?subject=Hola%20Rubén&body=¿Cómo%20estás?">
  Contacto
</a>

<!-- Tel: en móvil, abre el marcador con el número -->
<a href="tel:+34123456789">Llamar</a>

<!-- Download: fuerza la descarga en vez de abrir -->
<a href="documento.pdf" download>Descargar PDF</a>

<!-- Download con nombre personalizado -->
<a href="reporte.pdf" download="mi-reporte.pdf">Descargar</a>

Detalles que casi nadie explica

  • mailto: acepta ? para parámetros como subject, body y cc — entre los destinatarios van comas.
  • Los espacios en mailto: y tel: deben codificarse como %20 en los parámetros.
  • tel: solo funciona en dispositivos con app telefónica; en escritorio, no hace nada (a veces muestra un diálogo raro).
  • download solo funciona para archivos del mismo origen — si lo apuntas a un dominio distinto, el navegador puede ignorarlo.
5 El texto del enlace: accesibilidad

Un enlace que dice "haz clic aquí" es invisible para los lectores de pantalla. Cuando un usuario navega por_voice lee los enlaces uno a uno, sin contexto. Tu texto del enlace debe tener sentido por sí solo, fuera de la frase que lo rodea.

HTML · texto accesible vs no 
<!-- MAL: "aquí" no describe el destino -->
Para más información, haz clic <a href="/docs">aquí</a>.

<!-- CORRECTO: el texto describe a dónde vas -->
Lee la <a href="/docs">documentación completa</a>.

<!-- TRAMPA: la URL no es texto accesible -->
Visita <a href="https://mdn.dev">https://mdn.dev</a>.

<-- MEJOR: texto humano + URL visible -->
Visita <a href="https://mdn.dev">MDN</a>.

Cuando el diseño no deja texto claro: aria-label

A veces el diseño solo deja sitio para un icono. En ese caso, añade el atributo aria-label="..." con la descripción para el lector de pantalla.

HTML · aria-label en enlaces con icono 
<a href="#" aria-label="Ir al inicio">
  <svg>...icono de casa...</svg>
</a>
6 Tu ejercicio: índice con enlaces

Vas a construir una página con un índice que salta a tres secciones internas, un enlace externo seguro, un mailto y un tel. Lo que veías en cualquier blog con índice de contenidos — pero tuyo.

1

Crea enlaces.html con la estructura mínima

El molde del M01: <!DOCTYPE html>, <html lang="es">, <head> y <body>.

2

Un <nav> como índice interno

Tres enlaces con href="#seccion-1", "#seccion-2" y "#seccion-3". Mételos dentro de una <ul> con tres <li>.

3

Tres <section id="..."> con contenido

Cada una con un <h2> y un párrafo explicativo. Comprueba que al pulsar los enlaces del índice el navegador salta a la sección.

4

Un enlace externo seguro

Un enlace a https://developer.mozilla.org con target="_blank" y rel="noopener noreferrer". Comprueba que se abre en pestaña nueva.

5

Enlaces mailto: y tel:

Un <a href="mailto:tucorreo@ejemplo.com"> que abra la app de correo y un <a href="tel:+34123456789"> que abra el marcador. Comprueba el comportamiento en tu sistema.

7 Pruébalo aquí mismo

Pulsa Ejecutar para ver una página completa con índice interno, secciones, un enlace externo seguro y un enlace de contacto. Todo funcional.

HTML · enlaces.html 
<nav>
  <ul>
    <li><a href="#seccion-1">Inicio</a></li>
    <li><a href="#seccion-2">Artículos</a></li>
    <li><a href="#seccion-3">Contacto</a></li>
  </ul>
</nav>

<section id="seccion-1">
  <h2>Inicio</h2>
  <p>Bienvenido a mi página de ejemplo...</p>
</section>

<section id="seccion-2">
  <h2>Artículos</h2>
  <p>Aquí van mis publicaciones.</p>
  <p>Más info en <a href="https://developer.mozilla.org"
     target="_blank" rel="noopener noreferrer">
     Documentación MDN</a>.</p>
</section>

<section id="seccion-3">
  <h2>Contacto</h2>
  <p>
    <a href="mailto:hola@ejemplo.com">Escríbeme</a> ·
    <a href="tel:+34123456789">Llamar</a>
  </p>
</section>
