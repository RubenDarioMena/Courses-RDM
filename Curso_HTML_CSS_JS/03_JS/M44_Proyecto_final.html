2Requisitos que no se negocian

Tu proyecto pasa el corte si marca todas estas casillas. No son sugerencias: son la rúbrica de evaluación.

  • ✓
    HTML semántico: <header>, <main>, <section>, <article>, <footer>, con <meta> SEO y lang="es".
  • ✓
    CSS responsivo: Flexbox o Grid, custom properties para tokens, media queries o clamp(), tema claro/oscuro con toggle persistente.
  • ✓
    JS interactivo: DOM, eventos, fetch mock con <script type="application/json">, manejo de ok:false visible en el DOM.
  • ✓
    Organización: al menos 2 namespaces (App + Api) o 1 module-blob (M39). Nada de var x en el global.
  • ✓
    Persistencia: estado crítico en localStorage con JSON.stringify / JSON.parse. Maneja el caso null.
  • ✓
    Accesibilidad: alt en imágenes, label en inputs, contraste suficiente, foco visible, navegación con teclado.
  • ✓
    Calidad: console limpia, "use strict" activo, sin warnings en W3C Validator, Lighthouse a11y ≥ 90.
3Arquitectura recomendada

Cómo organizar el código (opción B: 2 namespaces)

No necesitas un framework. Un módulo blob al final del <body> con dos namespaces es suficiente y se siente como una app seria:

namespace App + Api (skeleton) 
"use strict";

// 1) Datos embebidos — simulan la respuesta de una API
<!-- <script type="application/json" id="mock-data">
  { "ok": true,  "items": [ ... ] }
</script> -->

// 2) Namespace Api: acceso a datos (real o mockeado)
const Api = {
  fakeFetch(path) {
    return new Promise(resolve => {
      setTimeout(() => {
        // Simula ok:false para enseñar manejo de errores
        if (path.includes('fail')) {
          resolve({ ok: false, error: 'recurso no encontrado' });
        } else {
          resolve({ ok: true, items: ['tarea 1', 'tarea 2'] });
        }
      }, 200);
    });
  }
};

// 3) Namespace App: estado, UI, persistencia
const App = {
  state: { tareas: [], tema: 'oscuro' },
  init() {
    // leer localStorage con fallback seguro
    try { this.state = JSON.parse(localStorage.getItem('app-state')) || this.state; }
    catch { /* mantén default */ }
  },
  save() { localStorage.setItem('app-state', JSON.stringify(this.state)); },
  render() { /* dibuja this.state.tareas en el DOM */ }
};

App.init();
console.log('arquitectura cargada:', Object.keys(App), Object.keys(Api));

// 4) Sincronización entre pestañas
window.addEventListener('storage', e => {
  if (e.key === 'app-state') { App.init(); App.render(); }
});

4Plan de trabajo en 5 pasos

Un orden probado para que no te atasques. Cada paso debe funcionar antes de pasar al siguiente; no acumules errores.

1

HTML y meta-datos

Estructura semántica + <script type="application/json"> con tus datos mock. Verifica en W3C Validator sin errores.

2

CSS responsivo + tema

Custom properties para tokens, Grid/Flex, media queries. Toggle de tema claro/oscuro con persistencia (M26 + M42).

3

JS: DOM + fetch mock

Renderiza datos del mock en el DOM, maneja ok:false con un mensaje visible y accesible.

4

Namespaces + localStorage

Refactoriza a App + Api. Persiste estado crítico. Sincroniza con evento storage.

5

QA: a11y, validator, console

Lighthouse a11y ≥ 90, W3C Validator sin errores, console limpia, navegación con teclado, foco visible.
