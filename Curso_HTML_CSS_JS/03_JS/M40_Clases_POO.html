1Anatomía de una clase

El molde y la pieza

Una clase es una plantilla. Una instancia es una pieza fabricada con ella. El constructor se ejecuta automáticamente al hacer new y es donde preparas el estado inicial. Los métodos viven en el prototipo, así que no se duplican en cada instancia: ahorras memoria.

Class fields y métodos estáticos

Los class fields son propiedades declaradas fuera del constructor (visibles en cada instancia). Los static pertenecen a la clase en sí, no a sus instancias: Usuario.fromJSON() sería un ejemplo típico, accesible sin hacer new.

Producto · class básica 
class Producto {
  // class field público
  categoria = 'general';

  constructor(nombre, precio) {
    this.nombre = nombre;
    this.precio = precio;
  }

  // método de instancia
  etiqueta() {
    return `${this.nombre} · $this.precio}`;
  }

  // método estático: se llama desde la clase, no desde la instancia
  static iva(precio) {
    return precio * 0.21;
  }
}

const p = new Producto('Café', 3.5);
alert(p.etiqueta());            // Café · $3.5
alert(Producto.iva(100));   // 21
console.log(p.categoria);         // general

2Herencia y privacidad real

extends y super()

Una subclase hereda métodos y campos del padre. super() llama al constructor del padre y debe ir antes de tocar this en la hija. Para sobrescribir un método del padre, lo defines con el mismo nombre y, si quieres, llamas a super.metodo() para reutilizar la lógica original.

Privados con #

El prefijo # declara un campo realmente privado: no se accede desde fuera, ni por accidente, ni por reflexión. Es la única privacidad real que ofrece JavaScript. Úsalo para encapsular invariantes (un saldo que no puede quedar negativo, un id que no debe reasignarse, etc.).

Jerarquía Animal + CuentaBancaria 
class Animal {
  constructor(nombre) { this.nombre = nombre; }
  hablar() { return '...'; }
}

class Perro extends Animal {
  hablar() { return 'Guau'; }
}

class Gato extends Animal {
  hablar() { return 'Miau'; }
}

class CuentaBancaria {
  // campo privado real
  #saldo = 0;

  constructor(titular, saldoInicial = 0) {
    this.titular = titular;
    this.#saldo = saldoInicial;
  }

  depositar(monto) {
    if (monto <= 0) throw new Error('monto inválido');
    this.#saldo += monto;
  }

  retirar(monto) {
    if (monto > this.#saldo) throw new Error('saldo insuficiente');
    this.#saldo -= monto;
  }

  // getter: saldo como propiedad, no como método
  get saldo() { return this.#saldo; }
}

// Uso
const rex = new Perro('Rex');
const mishi = new Gato('Mishi');
console.log(rex.nombre, '→', rex.hablar());  // Rex → Guau
console.log(mishi.nombre, '→', mishi.hablar()); // Mishi → Miau

const cta = new CuentaBancaria('Ada', 100);
cta.depositar(50);
console.log('saldo:', cta.saldo);  // saldo: 150

// cadena de prototipos
console.log(
  rex instanceof Perro,  // true
  rex instanceof Animal  // true (hereda)
);
// cta.#saldo  →  SyntaxError: privado, no se puede leer

3Clases vs factory functions

Dos formas válidas de fabricar

Una factory function es simplemente una función que devuelve un objeto. Tiene dos ventajas curiosas: no depende de this (más difícil de romper) y cierra sobre variables privadas del closure, sin necesidad del #.

El prototipo es lo que está debajo

Por debajo, las clases en JavaScript son azúcar sintáctico sobre prototipos. Cuando haces rex.hablar(), el motor busca el método en la instancia, y si no está, sube por la cadena hasta Perro.prototype, después a Animal.prototype, y finalmente a Object.prototype. Esa cadena es la cadena de prototipos.

Factory function equivalente 
// Equivalente a CuentaBancaria, pero con closure
function crearCuenta(titular, saldoInicial = 0) {
  let saldo = saldoInicial;  // privado por closure

  return {
    titular,
    depositar(m) { saldo += m; },
    retirar(m) {
      if (m > saldo) throw new Error('saldo insuficiente');
      saldo -= m;
    },
    get saldo() { return saldo; }
  };
}

const c = crearCuenta('Ada', 100);
c.depositar(25);
console.log('factory saldo:', c.saldo); // factory saldo: 125
// c.saldo = 99999  →  no funciona: solo hay getter

// Trazando la cadena de prototipos
const rex2 = new Perro('Rex');
let proto = Object.getPrototypeOf(rex2);
console.log('cadena:', proto === Perro.prototype);
proto = Object.getPrototypeOf(proto);
console.log('→ Perro → Animal:', proto === Animal.prototype);
proto = Object.getPrototypeOf(proto);
console.log('→ Animal → Object:', proto === Object.prototype);

¿Cuándo usar cada uno?

  • Clase: cuando hay una jerarquía clara y necesitas instanceof (p. ej. UI components, errores personalizados).
  • Factory: cuando quieres composición sobre herencia, evitar this, o devolver distintos objetos según la entrada.
4Getters, setters y validación

Propiedades que se comportan como métodos

Un get y un set te permiten exponer una propiedad que ejecuta lógica al leerla o al asignarla. Es perfecto para: validar valores antes de guardarlos, derivar un dato de otros (area a partir de ancho y alto), o proteger la API exponiendo solo lectura hacia fuera.

Rectangulo con getter/setter 
class Rectangulo {
  #ancho;
  #alto;

  constructor(ancho, alto) {
    this.#ancho = ancho;
    this.#alto  = alto;
  }

  get area() { return this.#ancho * this.#alto; }

  set ancho(v) {
    if (v <= 0) throw new Error('ancho debe ser positivo');
    this.#ancho = v;
  }
}

const r = new Rectangulo(4, 3);
console.log('area inicial:', r.area);  // area inicial: 12
r.ancho = 5;
console.log('area nueva:', r.area);    // area nueva: 15
// r.ancho = -1  →  Error: ancho debe ser positivo
