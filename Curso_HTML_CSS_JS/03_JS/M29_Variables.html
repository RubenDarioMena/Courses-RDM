MÓDULO 29 · VARIABLES

Variables: let, const y var

Una variable es una caja con una etiqueta: guardas un valor y lo recuperas cuando quieras. JavaScript te da tres palabras para crear esas cajas. Cada una tiene reglas distintas. Hoy vas a dominarlas.

3 palabras clave Scope y hoisting ~12 min de lectura
1Las tres formas de declarar

var, let y const no son intercambiables

Las tres crean variables, pero se comportan diferente. Afectan al scope, a la mutabilidad y al hoisting de formas distintas.

var

La antigua. Scope de función, se reasigna, se redeclara y se "eleva" (hoisting). Origen: 1995. Úsala solo en código legacy.

var nombre = "Ana";

let

La moderna mutable. Scope de bloque { }, se reasigna, pero no se redeclara en el mismo bloque. Origen: ES6 (2015).

let edad = 30;

const

La moderna inmutable. Scope de bloque, no se reasigna. Para objetos/arrays, las propiedades internas sí pueden cambiar.

const PI = 3.1416;

// 1. const con un objeto: la referencia es fija, el contenido no
const usuario = { nombre: "Ana", edad: 28, activo: true };
console.log("Perfil inicial:", usuario.nombre, usuario.edad);

// 2. Reasignar const lanza TypeError (lo capturamos)

catch(e) { console.log("Error capturado:", e.message); }

// 3. let SÍ se reasigna
let edadNueva = usuario.edad;

// 4. Block scope: el let interno NO contamina fuera
{ let edadNueva = "secreto"; console.log("Dentro del bloque:", edadNueva); }
console.log("Fuera del bloque:", edadNueva);

// 5. Hoisting: la función declarada abajo se eleva

3Scope, hoisting y TDZ

Los tres scopes

El scope es la "zona" donde una variable es visible: global, de función y de bloque { }. var respeta solo el de función; let y const respetan el de bloque.

Hoisting y TDZ: JS eleva las declaraciones al inicio del scope. var se eleva con undefined. let y const quedan en la TDZ: existen, pero tocarlas antes de declararlas lanza ReferenceError.

4Reglas de nombrado y buenas prácticas

Nombres válidos y camelCase

Un nombre debe empezar con letra, $ o _, no con número, y no puede ser palabra reservada (if, for, class...). La convención es camelCase: primera palabra en minúscula, siguientes con mayúscula inicial.

nombreUsuario · totalFactura · esMayor · _privado · MAX_INTENTOS (constantes)
Mal: 1usuario (empieza por número), class (reservada), nombre usuario (espacios)

const por defecto

Regla de oro: empieza con const. Cambia a let solo cuando sepas que se reasignará. Evita var salvo en legacy. const comunica intención: "esto no debe cambiar".
