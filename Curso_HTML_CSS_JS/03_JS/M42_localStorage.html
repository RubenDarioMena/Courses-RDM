localStorage: persiste en el navegador

El navegador te regala una pequeña base de datos clave/valor que sobrevive a recargas, cierres de pestaña e incluso al reinicio del equipo. No necesitas servidor, ni cookies, ni fetch. Es el lugar perfecto para preferencias, borradores, listas locales y cualquier dato que no merezca salir al backend.

1La API mínima

localStorage vs sessionStorage

Ambos exponen la misma API (los mismos métodos, misma sintaxis). La diferencia está en la duración: localStorage sobrevive hasta que el usuario borre los datos del sitio o cierre sesión; sessionStorage se borra al cerrar la pestaña. Si tu dato debe vivir más allá de la sesión actual, necesitas localStorage.

5 métodos para dominar el mundo

  • setItem(k, v) — guarda un par. Los valores siempre son strings.
  • getItem(k) — devuelve el valor o null si no existe.
  • removeItem(k) — borra un par específico.
  • clear() — borra todo el almacenamiento de tu origen.
  • key(i) — devuelve el nombre de la clave en la posición i.
CRUD básico con localStorage 
// Crear / actualizar
localStorage.setItem('usuario', 'Ada Lovelace');
localStorage.setItem('nivel', '42');  // se guarda como string

// Leer
console.log(localStorage.getItem('usuario'));
console.log(localStorage.getItem('inexistente')); // null
console.log('total claves:', localStorage.length);

// Recorrer todas las claves
for (let i = 0; i < localStorage.length; i++) {
  const k = localStorage.key(i);
  console.log(k, '→', localStorage.getItem(k));
}

// Borrar
localStorage.removeItem('nivel');
localStorage.clear();  // borra TODO del origen

2JSON + localStorage

El truco que necesitas saber

localStorage solo guarda strings. Para guardar un objeto, array, número o booleano, serializa con JSON.stringify y deserializa con JSON.parse. Recuerda: si haces getItem de una clave inexistente, recibes null, no undefined. Siempre comprueba antes de parsear.

Guardar objetos completos 
// Una app de notas: array de objetos
const notas = [
  { id: 1, texto: 'Estudiar JS',     hecho: false },
  { id: 2, texto: 'Terminar el módulo', hecho: true  }
];

// guardar
localStorage.setItem('mis-notas', JSON.stringify(notas));

// leer (con fallback seguro)
const raw = localStorage.getItem('mis-notas');
const recuperadas = raw ? JSON.parse(raw) : [];
console.log('recuperadas:', recuperadas);
console.log('hecho[1]:', recuperadas[1].hecho);

// helper DRY: evita repetir JSON.parse/stringify
const storage = {
  get(k, fallback = null) {
    const v = localStorage.getItem(k);
    try { return v ? JSON.parse(v) : fallback; }
    catch { return fallback; }
  },
  set(k, v) { localStorage.setItem(k, JSON.stringify(v)); }
};

storage.set('preferencias', { tema: 'oscuro', fuente: 16 });
console.log('helper:', storage.get('preferencias'));

3Sincronizar pestañas

El evento storage

Si abres la misma app en dos pestañas y modificas localStorage en una, la otra pestaña recibe un evento storage en window. Eso te permite sincronizar UI entre pestañas: un cambio en una actualiza la otra automáticamente. No recibes el evento en la pestaña que hizo el cambio, solo en el resto.

Información que trae el evento

  • e.key — la clave que cambió (o null si fue clear()).
  • e.oldValue / e.newValue — antes y después.
  • e.url — la URL de la pestaña que disparó el cambio.
  • e.storageArea — qué storage cambió (local o session).
Escuchar cambios entre pestañas 
// Registrar un listener
const handler = (e) => {
  console.log('cambió:', e.key, '→', e.newValue);
  // aquí re-renderizar la lista, recargar prefs, etc.
};
window.addEventListener('storage', handler);

// simular el cambio (esto NO dispara el evento en esta pestaña)
localStorage.setItem('contador', '42');
console.log('cambié en esta pestaña; el listener no se dispara aquí');

// limpiar
window.removeEventListener('storage', handler);

4Límites y seguridad

Lo que tienes que saber antes de abusar

  • Capacidad: ~5 MB por origen en la mayoría de navegadores. Si excedes, recibes QuotaExceededError.
  • Es síncrono: cada llamada bloquea el hilo principal. No guardes megabytes en cada keystroke.
  • Es de texto plano: cualquier extensión, devtools o script inyectado puede leerlo. No guardes contraseñas, tokens, ni datos personales.
  • Es por origen: dos apps en el mismo dominio comparten el mismo storage. Usa prefijos (app1.user, app2.user).
  • No es para blobs grandes: para eso existe IndexedDB.
