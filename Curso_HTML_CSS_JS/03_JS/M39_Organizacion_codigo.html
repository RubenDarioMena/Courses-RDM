Organización: namespaces y ES Modules

Tu JS funciona. Pero si tu <script> tiene 500 líneas, todo se vuelve spaghetti. Aquí verás cómo estructurar el código con namespaces, IIFE y ES Modules — incluso sin servidor, gracias al truco de los blob URLs.

Globales IIFE ES Modules + blob
1 El problema: globales que se pisan

Por defecto, todo lo que declaras con var en un <script> va al objeto global (window en el navegador). Dos scripts que declaren la misma variable se pisan. Con 5 ficheros JS, esto es un infierno.

JavaScript · el problema 
// app.js
var usuario = 'Ana';
function saludar() { console.log('Hola ' + usuario); }

// libs.js (terceros, sin saber)
var usuario = '[email protected]';   // ← ¡PISÓ mi variable!
2 Namespacing: un objeto contenedor

La forma más simple: meterlo todo en un objeto. Solo el objeto vive en global, sus propiedades son tuyas.

JavaScript · namespace 
const App = {
  estado: { usuario: 'Ana', contador: 0 },
  init() { console.log('App lista'); },
  saludar() { console.log('Hola ' + this.estado.usuario); }
};

App.init();
App.saludar();
3 IIFE + revealing module: privados de verdad

Una IIFE (Immediately Invoked Function Expression) es una función que se ejecuta al definirse. Dentro puedes tener variables que nadie de fuera puede ver. El revealing module pattern es la versión que devuelve un objeto con solo lo público.

JavaScript · IIFE + revealing module 
const Contador = (function(){
  let n = 0;   // privado, nadie de fuera lo ve

  return {
    incrementar() { n++; return n; },
    obtener() { return n; },
    resetear() { n = 0; }
  };
})();

Contador.incrementar();  // 1
Contador.incrementar();  // 2
Contador.n;             // undefined ← privado
4 ES Modules via blob: offline y en file://

Los ES Modules (import / export) son la forma estándar de organizar JS moderno. El problema: en file:// los navegadores los bloquean por CORS. El truco: crear el módulo como un Blob y darle una URL temporal con URL.createObjectURL. Funciona offline.

JavaScript · ESM via blob (offline, sin servidor) 
// 1. Escribes el código del módulo como string
const codigo = `export function suma(a,b){ return a+b; }
export const PI = 3.14159;`;

// 2. Lo conviertes en un Blob y le das URL
const blob = new Blob([codigo], { type: 'application/javascript' });
const url = URL.createObjectURL(blob);

// 3. Lo importas dinámicamente
const mod = await import(url);
console.log(mod.suma(2, 3));   // 5

En producción real los módulos son ficheros .js con type="module" en el <script> y un servidor. En este curso usamos blob URLs porque no hay servidor, todo es local. El patrón de tu código es idéntico.

5 Caja teórica: CommonJS, ESM y bundlers

En el mundo real verás dos sistemas de módulos: CommonJS (Node.js clásico, usa require('modulo')) y ES Modules (estándar, usa import/export). Y verás bundlers como Vite, esbuild o Webpack que toman todos tus imports分散 y los empaquetan en uno o pocos ficheros para el navegador.

CommonJS
const x = require('x')
Node.js clásico. require sincrónico. module.exports. No funciona en el navegador sin bundler.
ES Modules
import {x} from 'x'
Estándar oficial. import/export. Sí funciona nativo en navegadores modernos con type="module".
Bundler (Vite/esbuild)
vite build
Toma tus imports, resuelve dependencias, minifica, y produce un bundle listo para producción. Lo usa casi todo el mundo hoy.
