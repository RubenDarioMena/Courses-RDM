Generador de output: de formulario a texto final

El tester llena el formulario y, a la derecha, la herramienta genera automáticamente el texto que pegará en el issue tracker. Ese texto se construye recorriendo el schema, aplicando plantillas y modo joined o lines. En este módulo vemos cómo buildOutput convierte los valores del formulario en el texto final.

⚡ JS Avanzado ~12 min de lectura Nivel: intermedio
1La idea en una imagen

Imagina una máquina embutidora: por un lado entran los valores del formulario (team, región, mapa...) y por el otro sale un texto formateado listo para pegar. Cada campo tiene su plantilla ("COD {value}" → "COD 12345") y la sección decide si todo va en una línea (joined) o en líneas separadas (lines).

2buildOutput: recorrer secciones y aplicar plantillas

La función que genera el texto final

buildOutput(inst) es el corazón del generador. Recibe una instancia (los valores del bug) y produce un objeto con full (texto completo), summary (primera línea) y description (el resto). Estos chunks sirven para los botones "Copiar resumen" y "Copiar descripción".

JavaScript — buildOutput (simplificado)
function buildOutput(inst) {
  const form = getForm(inst.formId);
  const fx = evalFieldRules(form, inst); // campos ocultos
  const blocks = [];

  form.sections.forEach(sec => {
    const lines = [];
    if (sec.mode === "joined") {
      // Todos los campos en una línea con separadores
      let line = "";
      sec.fields.forEach(field => {
        if (fx[field.id].hidden) return;
        const part = fieldOutputPart(field, inst);
        if (part == null) return;
        line += (line ? sec.sep : "") + part;
      });
      if (line) lines.push(line);
    } else {
      // Cada campo aporta su(s) línea(s)
      sec.fields.forEach(field => {
        if (fx[field.id].hidden) return;
        const part = fieldOutputPart(field, inst);
        if (part != null) lines.push(...part);
      });
      if (sec.heading) lines.unshift(sec.heading);
    }
    if (lines.length) blocks.push({ lines, noGap: !!sec.noGap });
  });

  return { full: out.join("\n"), summary, description };
}
3Modo joined: todo en una línea

Separadores y plantillas que se concatenan

En modo joined, todos los campos de la sección se unen en una sola línea. El separador puede ser " - " (por defecto), " " o cualquier texto. Cada campo tiene una plantilla que transforma su valor: "COD {value}" → "COD 12345".

JSON — sección joined del schema
{
  "id": "resumen",
  "label": "Resumen (encabezado)",
  "mode": "joined",
  "sep": " - ",
  "fields": [
    { "id": "team", "label": "Team", "type": "text" },
    { "id": "version", "label": "Versión", "type": "text" }
  ]
}
// Output: "QA EU - 1.0.4567 - PC(MSS) - MP - Highrise ..."
4Modo lines: cada campo en su línea

heading, joinPrev y perLine

En modo lines, cada campo aporta una o más líneas. Tres propiedades controlan cómo se formatean:

1

heading

Encabezado que se antepone a las líneas de la sección. Ej: "+Información de Compilación:+ → se pone como primera línea.

2

joinPrev

El campo se une a la línea anterior (sin salto de línea). Ej: la zona horaria tz se pega al final de la línea del timestamp.

3

perLine

Aplica la plantilla a cada línea escrita. Ej: los pasos para reproducir (uno por línea) se convierten en "# Paso 1", "# Paso 2", etc.

5omitValue y emptyAs: valores vacíos

Cuándo omitir y cuándo sustituir

Dos propiedades controlan el comportamiento cuando un campo está vacío:

1

omitValue

Si el valor coincide con omitValue, el campo se omite del output. Ej: omitValue: "N/A" → si BSP CL es "N/A", no aparece en el output.

2

emptyAs

Si el campo está vacío, se usa emptyAs como valor en la plantilla. Ej: emptyAs: "N/A" → si CCS está vacío, el output dice "CCS/FFOTD: N/A".

6Chunks: summary y description

Por qué el output se divide en dos

El output se divide en summary (la primera línea, que se genera en la sección joined) y description (todas las demás secciones). Así el tester puede copiar solo el resumen con el botón "Copiar resumen" para el título del issue, o copiar todo con "Copiar todo" para el cuerpo.

7Tu primer momento: generar output

Pulsa Ejecutar para ver cómo buildOutput recorre un schema de 2 secciones (una joined y una lines) y genera el texto final a partir de los valores.

JavaScript — buildOutput simplificado 
// Schema simplificado de 2 secciones
var sections = [
  { mode:"joined", sep:" - ", fields:[
    { id:"team", template:"{value}" },
    { id:"version", template:"{value}" }
  ]},
  { mode:"lines", heading:"+Build:", fields:[
    { id:"cl", template:"CL: {value}" }
  ]}
];
var values = { team:"QA", version:"1.0.4567", cl:"12345" };

// Generar output:
var lines = [];
sections[0].fields.forEach(function(f){
  var v = values[f.id];
  if(v) lines.push(f.template.replace("{value}", v));
});
console.log(lines.join(" - ")); // resumen
console.log("+Build:");
console.log("CL: " + values.cl);
