Persistencia, exportación y cierre del sistema

La herramienta guarda todo en el navegador con localStorage, exporta un HTML autocontenido con tu config modificada, y se arranca con una secuencia precisa. En este último módulo cerramos el sistema viendo cómo se guarda, se exporta y se reinicia.

1La idea en una imagen

Imagina un cuaderno que se escribe a sí mismo: cada vez que escribes algo, el cuaderno lo guarda automáticamente 300ms después. Y si quieres compartir ese cuaderno con su configuración, pulsas un botón y se descarga como una copia nueva que otros pueden usar sin instalar nada.

2scheduleSave + debounce: guardar en localStorage

El patrón debounce: no guardar en cada tecla

Si la herramienta guardara en localStorage cada vez que el tester pulsa una tecla, haría decenas de escrituras por segundo. La solución es debounce: esperar a que el usuario deje de escribir 300ms antes de guardar. Si escribe otra tecla dentro de esos 300ms, el contador se reinicia.

JavaScript — scheduleSave con debounce
let saveTimer = null;

function scheduleSave() {
  if (saveTimer) clearTimeout(saveTimer);  // cancela el anterior
  setSaveIndicator("saving");       // punto ámbar
  saveTimer = setTimeout(() => {
    saveAll();                        // escribe en localStorage
    setSaveIndicator("saved");       // punto verde
  }, 300);                              // espera 300ms
}

saveAll y loadSession: config y sesión por separado

La herramienta guarda dos cosas en localStorage:

1

CONFIG_KEY ("bug_tool_v2_config")

El schema + los datos (listas, reglas). Es lo que el equipo de Database edita.

2

SESSION_KEY ("bug_tool_v2_session")

Las instancias de bugs abiertas y las preferencias (pestaña activa, tiles colapsadas).

3exportToolHtml: el truco del HTML autocontenido

PRISTINE_HTML: el ADN original

Al cargar la página, antes de que JS pinte nada, se captura el HTML completo: const PRISTINE_HTML = document.documentElement.outerHTML. Esto es el "ADN" del archivo: el HTML con el JSON original sin tocar.

Reemplazar el JSON y descargar

Cuando el usuario pulsa "Exportar herramienta", la función busca el bloque vanillaConfig dentro de PRISTINE_HTML, lo reemplaza con el config actual (serializado con JSON.stringify), y descarga el resultado como un nuevo bug_tool.html. El nuevo archivo es idéntico al original pero con el JSON actualizado.

JavaScript — exportToolHtml (simplificado)
function exportToolHtml() {
  // Serializar la config actual, escapando 
  const json = JSON.stringify(config, null, 2);

  // Buscar el bloque vanillaConfig en el HTML prístina
  const marker = 'id="vanillaConfig">';
  const start = PRISTINE_HTML.indexOf(marker);
  const end = PRISTINE_HTML.indexOf(SCRIPT_END, start);

  // Reemplazar el JSON y descargar como nuevo .html
  const out = PRISTINE_HTML.slice(0, start + marker.length)
            + "\n" + json + "\n"
            + PRISTINE_HTML.slice(end);

  downloadFile("bug_tool.html", out);
}

El escapamiento de </script>

Si el JSON contiene el texto </script>, el navegador cerraría el <script> prematuramente. Por eso JSON.stringify se post-procesa reemplazando </" por <\/", y SCRIPT_END se construye en dos partes para evitar que el propio código fuente rompa el parser HTML.

4CSV import/export: datos sin tocar código

Dos CSVs para dos audiencias

La herramienta tiene dos flujos de CSV para el equipo de Database:

1

bug_data.csv

Listas y reglas: regions, platforms, maps, pois, kw_count, etc. El equipo de Database lo edita en Excel y lo importa.

2

bug_fields.csv

Schema de formularios: secciones, campos, tipos, plantillas, validaciones. Define la estructura del formulario sin tocar JavaScript.

El parser de CSV (parseCsvLine) maneja comillas, comas dentro de textos entrecomillados y saltos de línea. La exportación usa csvEscape para envolver valores con comas en comillas dobles.

5boot(): la secuencia de arranque

El orden importa

Cuando el navegador termina de cargar el HTML, se ejecuta boot(). El orden de las operaciones es crítico: si se renderiza antes de cargar la config, no hay nada que pintar.

JavaScript — boot()
function boot() {
  loadVanillaConfig();     // 1. Leer JSON del <script type="application/json">
  migrateListsToTree(vanilla); // 2. Migrar listas a estructura de árbol
  loadConfig();           // 3. Leer de localStorage o clonar vanilla
  loadSession();          // 4. Restaurar instancias y preferencias

  // 5. Sanear sesión: filtrar instancias de forms que ya no existen
  state.instances = state.instances.filter(i => getForm(i.formId));

  // 6. Cablear eventos estáticos (botones, menús de la barra superior)
  wireStaticControls();
  wireMediaPanel();

  // 7. Renderizar todo por primera vez
  refreshAll();
}
6beforeunload y visibilitychange

La última oportunidad de guardar

Si el usuario cierra la pestaña o cambia de aplicación, la herramienta tiene dos eventos para guardar antes de que sea tarde:

1

beforeunload

Se dispara justo antes de cerrar la pestaña. La herramienta llama saveAll() aquí. No hay tiempo para debounce: hay que escribir síncrono.

2

visibilitychange

Se dispara cuando el usuario cambia a otra pestaña del navegador (la página se oculta). También dispara saveAll() para no perder cambios.
