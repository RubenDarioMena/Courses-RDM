MODULO 15 · JS AVANZADO — VALIDACION

Validacion: required, regex y condiciones

El motor de validacion es el corazon de la herramienta. No se limita a comprobar si un campo esta vacio: verifica patrones regex, evalua condiciones entre campos (si A esta vacio, B es obligatorio) y puede mostrar, ocultar, deshabilitar o rellenar campos dinamicamente. Todo esto sin re-renderizar el formulario entero.

⚡ JS Avanzado ~14 min de lectura Nivel: intermedio-avanzado
1La idea en una imagen

Imagina un inspector de aduanas. Cada campo del formulario es una maleta. El inspector revisa tres cosas: que no este vacia (required), que el contenido coincida con un patron (regex) y que lo que lleva una maleta tenga sentido con lo que lleva la maleta de al lado (condiciones entre campos). Si algo falla, pone una etiqueta roja en la maleta — no la tira, solo la marca.

2revalidate(inst): el motor principal

Una sola funcion que lo orquesta todo

La funcion revalidate(inst) es el punto de entrada. Recibe la instancia del formulario, recorre todos los campos definidos en config.fields, aplica las reglas de cada uno y despues actualiza los errores en pantalla. El diseno es deliberadamente simple: una sola llamada valida todo el formulario.

JavaScript — revalidate (estructura)
function revalidate(inst) {
  const errors = {};

  config.fields.forEach(field => {
    // 1. Evaluar reglas del campo (show/hide/disable)
    evalFieldRules(field, inst);

    // 2. Si el campo es visible, validar contenido
    if (isVisible(field, inst)) {
      const val = inst.values[field.id] || "";

      // 3. required: comprobar que no este vacio
      if (field.required && !val.trim()) {
        errors[field.id] = "Este campo es obligatorio";
      }
      // 4. regex: comprobar patron
      else if (field.regex &&
                 !new RegExp(field.regex).test(val)) {
        errors[field.id] = field.regexMsg || "Formato invalido";
      }
    }
  });

  // 5. Reflejar errores en el DOM
  reflectErrors(errors);
  inst.errors = errors;
  return Object.keys(errors).length === 0;
}

El retorno es true si no hay errores, false si los hay. Asi el boton de enviar puede comprobar if (revalidate(inst)) enviar() y solo procede si todo esta correcto.

3evalFieldRules: show, hide, disable, setDefault

Campos que aparecen y desaparecen segun el contexto

No todos los campos son siempre visibles. Si el tipo de bug es "visual", aparece el campo " captura de pantalla". Si es "servidor", aparece "log de error". La funcion evalFieldRules evalua las reglas de cada campo para decidir si se muestra, se oculta, se deshabilita o se rellena con un valor por defecto.

JavaScript — evalFieldRules
function evalFieldRules(field, inst) {
  const el = document.getElementById("field-" + field.id);
  if (!el) return;

  // Regla show: si la condicion es falsa, ocultar
  if (field.show) {
    const visible = evalCondition(field.show, inst);
    el.style.display = visible ? "" : "none";
    if (!visible) delete inst.values[field.id];
  }

  // Regla disable: si la condicion es falsa, deshabilitar
  if (field.disable) {
    const enabled = evalCondition(field.disable, inst);
    el.disabled = !enabled;
  }

  // Regla setDefault: rellenar si esta vacio
  if (field.setDefault && !inst.values[field.id]) {
    inst.values[field.id] = field.setDefault;
    el.value = field.setDefault;
  }
}

Cada regla es opcional y independiente. Un campo puede tener show sin disable, o las tres reglas a la vez. El orden importa: primero se evalua show (si el campo no es visible, no tiene sentido evaluar el resto).

4evalCondition: el lenguaje de condiciones

Cinco operadores para expresar cualquier condicion

Las reglas show, disable y setDefault usan condiciones. En lugar de inventar un DSL complejo, la herramienta usa cinco operadores simples que cubren todos los casos necesarios.

JavaScript — evalCondition
function evalCondition(cond, inst) {
  const val = inst.values[cond.field] || "";
  const target = cond.value;

  switch (cond.op) {
    case "empty":     return val.trim() === "";
    case "notEmpty":  return val.trim() !== "";
    case "equals":    return val === target;
    case "matches":   return new RegExp(target).test(val);
    case "equalsField": return val === inst.values[target];
    default:       return false;
  }
}

// Ejemplo de configuracion:
// show: { field: "tipo", op: "equals", value: "visual" }
// disable: { field: "estado", op: "equals", value: "cerrado" }
1

empty / notEmpty

Comprueba si un campo esta vacio o no. Util para mostrar campos opcionales solo si otro tiene contenido.

2

equals

Compara con un valor literal. Si tipo === "visual", muestra el campo captura.

3

matches

Compara con un regex. Si el servidor coincide con el patron de IP, habilita el campo de puerto.

4

equalsField

Compara dos campos entre si. Util para confirmar que dos valores coinciden (como password y confirmar password).

5reflectErrors: update in place vs re-render

Por que no re-renderizar el formulario entero

La tentacion natural al encontrar un error es re-pintar todo el formulario con los mensajes de error incluidos. Pero eso destruira el estado del DOM: inputs que pierden el foco, selects que se resetean, scroll que se reinicia. La solucion es reflectErrors, que actualiza los errores in place sin re-renderizar.

JavaScript — reflectErrors (update in place)
function reflectErrors(errors) {
  // 1. Limpiar errores anteriores
  document.querySelectorAll(".invalid")
    .forEach(el => el.classList.remove("invalid"));
  document.querySelectorAll(".field-error")
    .forEach(el => { el.textContent = ""; el.style.display = "none"; });

  // 2. Marcar campos con error (sin re-render)
  Object.keys(errors).forEach(id => {
    const input = document.getElementById("field-" + id);
    const errBox = document.getElementById("error-" + id);
    if (input) input.classList.add("invalid");
    if (errBox) {
      errBox.textContent = errors[id];
      errBox.style.display = "block";
    }
  });
}

El patron es: limpiar todo (quitar clases .invalid, vaciar textos de error) y despues marcar solo los nuevos errores. El DOM no se reconstruye, solo se anaden y quitan clases y textos. El usuario no pierde el foco ni el scroll.

6Tu primer momento: validar un formulario

Pulsa Ejecutar para ver como revalidate procesa un formulario con tres campos: un campo requerido vacio (falla), un campo con regex que no coincide (falla) y un campo correcto (pasa).

JavaScript — simulacion de revalidate 
// Simular el motor de validacion
var inst = {
  values: { titulo: "", email: "ruben@", cuerpo: "Todo ok" },
  errors: {}
};

var fields = [
  { id: "titulo", required: true },
  { id: "email",   required: true, regex: "^.+@.+\\..+$", regexMsg: "Email invalido" },
  { id: "cuerpo",  required: true }
];

fields.forEach(function(f) {
  var v = inst.values[f.id] || "";
  if (f.required && !v.trim()) {
    inst.errors[f.id] = "Obligatorio";
  } else if (f.regex && !new RegExp(f.regex).test(v)) {
    inst.errors[f.id] = f.regexMsg;
  }
  console.log(f.id + ": " + (inst.errors[f.id] || "OK"));
});
console.log("Total errores: " + Object.keys(inst.errors).length);
