MODULO 16 · JS AVANZADO — EXPRESIONES

Motor de expresiones booleanas

Las condiciones simples del modulo anterior (empty, equals, matches) no bastan cuando necesitas combinar reglas. "Si A esta vacio O B coincide con el patron Y C no es igual a D" requiere un motor de expresiones booleanas. En este modulo lo construiremos desde cero: un tokenizer, un parser de descenso recursivo, un evaluador de AST y un validador de sintaxis para feedback en vivo.

⚡ JS Avanzado ~16 min de lectura Nivel: avanzado
1La idea en una imagen

Imagina que condiciones simples son piezas de Lego sueltas. El motor de expresiones es el manual de instrucciones que te dice como encajarlas con conectores (OR, AND, NOT) y parentesis. El resultado es una torre que se evalua de arriba abajo y solo tiene dos posibles resultados: true o false.

2Gramatica: or → and → not → primary

Precedencia de operadores

El motor respeta la misma precedencia que casi todos los lenguajes: OR es el mas debil, AND es mas fuerte, NOT es aun mas fuerte, y las comparaciones (primary) son las hojas del arbol. Los parentesis rompen la precedencia.

Gramatica BNF simplificada
// La jerarquia de precedencia (de mas debil a mas fuerte):
expr     := orExpr
orExpr   := andExpr ( "OR" andExpr )*
andExpr  := notExpr ( "AND" notExpr )*
notExpr  := "NOT" notExpr | primary
primary  := "(" expr ")" | comparison
comparison := word op (word | str | ref)

// Ejemplo: a empty OR b = "foo" AND NOT c matches @re
// Se agrupa como: (a empty) OR ((b = "foo") AND (NOT (c matches @re)))

Esta jerarquia significa que AND agrupa mas fuerte que OR: a OR b AND c se lee como a OR (b AND c), no como (a OR b) AND c. Es el mismo comportamiento que en Python, JavaScript o SQL.

3tokenizeExpr: de caracteres a tokens

El lexer: convertir texto en fichas

El primer paso es tokenizar: recorrer la cadena caracter por caracter y producir una lista de tokens. Hay cuatro tipos de tokens: word (identificadores como nombres de campo), str (cadenas entre comillas), ref (referencias con @) y op (operadores como = o palabras clave como OR AND NOT empty).

JavaScript — tokenizeExpr
function tokenizeExpr(src) {
  const tokens = [];
  let i = 0;
  while (i < src.length) {
    const c = src[i];
    if (c === " " || c === "\t") { i++; continue; }
    if (c === "(" || c === ")") {
      tokens.push({ t: "paren", v: c }); i++;
    } else if (c === '"') {           // string
      let s = ""; i++;
      while (i < src.length && src[i] !== '"') s += src[i++];
      i++; tokens.push({ t: "str", v: s });
    } else if (c === "@") {            // referencia
      let s = ""; i++;
      while (i < src.length && /\w/.test(src[i])) s += src[i++];
      tokens.push({ t: "ref", v: s });
    } else if (/[=<>!]/.test(c)) {        // operador de comparacion
      let s = c; i++;
      while (i < src.length && /[=<>!]/.test(src[i])) s += src[i++];
      tokens.push({ t: "op", v: s });
    } else {                           // palabra (word u operador)
      let s = "";
      while (i < src.length && /[\w\.]/.test(src[i])) s += src[i++];
      if (s === "OR" || s === "AND" || s === "NOT" ||
          s === "empty" || s === "notEmpty" ||
          s === "equals" || s === "matches" ||
          s === "equalsField") {
        tokens.push({ t: "op", v: s });
      } else {
        tokens.push({ t: "word", v: s });
      }
    }
  }
  return tokens;
}
4parseExpr: parser de descenso recursivo

De tokens a arbol (AST)

El parser consume la lista de tokens y construye un AST (Abstract Syntax Tree). Cada nivel de la gramatica es una funcion: parseOr llama a parseAnd, que llama a parseNot, que llama a parsePrimary. Es descenso recursivo: cada funcion consume lo que puede y devuelve el control al nivel superior.

JavaScript — parseExpr (descenso recursivo)
function parseExpr(tokens) {
  let pos = 0;
  const peek = () => tokens[pos];
  const next = () => tokens[pos++];

  function parseOr() {
    let left = parseAnd();
    while (peek() && peek().v === "OR") {
      next();
      const right = parseAnd();
      left = { type: "or", left, right };
    }
    return left;
  }

  function parseAnd() {
    let left = parseNot();
    while (peek() && peek().v === "AND") {
      next();
      const right = parseNot();
      left = { type: "and", left, right };
    }
    return left;
  }

  function parseNot() {
    if (peek() && peek().v === "NOT") {
      next();
      return { type: "not", inner: parseNot() };
    }
    return parsePrimary();
  }

  function parsePrimary() {
    if (peek().v === "(") {
      next();
      const e = parseOr();
      if (peek().v === ")") next();
      return e;
    }
    // comparison: field op operand
    const field = next().v;
    const op = next().v;
    const operand = next();
    return { type: "cmp", field, op,
             value: operand.v, valueType: operand.t };
  }

  return parseOr();
}

Cada nivel se llama a si mismo o al nivel inferior, y los parentesis reinician el ciclo en parseOr. El resultado es un arbol donde cada nodo es {type, ...}.

5evalAst: evaluar el arbol

Recorrer el AST y devolver true/false

La funcion evalAst recibe el AST y la instancia del formulario. Con un switch sobre node.type decide que hacer: or usa some, and usa every, not niega, cmp delega en evalCondition del modulo anterior, y ref recursa con proteccion anti-ciclo.

JavaScript — evalAst
function evalAst(node, inst, seen) {
  seen = seen || new Set();

  switch (node.type) {
    case "or":
      return [node.left, node.right]
        .some(n => evalAst(n, inst, seen));

    case "and":
      return [node.left, node.right]
        .every(n => evalAst(n, inst, seen));

    case "not":
      return !evalAst(node.inner, inst, seen);

    case "cmp":
      return evalCondition({
        field: node.field, op: node.op,
        value: node.value
      }, inst);

    case "ref":
      // Anti-ciclo: si ya vimos esta ref, abortar
      if (seen.has(node.name)) {
        throw new Error("Ciclo en ref: " + node.name);
      }
      seen.add(node.name);
      const refExpr = inst.refs[node.name];
      const refAst = parseExpr(tokenizeExpr(refExpr));
      return evalAst(refAst, inst, seen);

    default:
      throw new Error("Tipo desconocido: " + node.type);
  }
}

La proteccion anti-ciclo con Set seen es critica: si @re referencia a @rf y @rf referencia de vuelta a @re, sin el Set el motor entraria en un bucle infinito. Con seen.has(), se detecta y se lanza un error descriptivo.

6exprError: feedback en vivo

Validar sintaxis antes de evaluar

El usuario escribe la expresion en un textarea. Si hay un error de sintaxis (parentesis sin cerrar, operador sin operando), no se puede evaluar — pero el usuario necesita ver el error mientras escribe, no despues de pulsar "Enviar". La funcion exprError intenta tokenizar y parsear, y si falla, devuelve el mensaje de error.

JavaScript — exprError
function exprError(src) {
  if (!src || !src.trim()) return "Expresion vacia";

  try {
    const tokens = tokenizeExpr(src);
    if (tokens.length === 0) return "Sin tokens";

    const ast = parseExpr(tokens);

    // Verificar parentesis balanceados
    let depth = 0;
    tokens.forEach(t => {
      if (t.v === "(") depth++;
      if (t.v === ")") depth--;
    });
    if (depth !== 0)
      return "Parentesis desbalanceados";

    return null;  // sin error
  } catch (e) {
    return e.message;
  }
}

// Uso en el textarea:
input.addEventListener("input", () => {
  const err = exprError(input.value);
  errBox.textContent = err || "";
  errBox.style.display = err ? "block" : "none";
});
7Tu primer momento: tokenizar una expresion

Pulsa Ejecutar para ver como tokenizeExpr convierte la expresion ('x empty OR y = "foo") AND NOT z matches @re' en una lista de tokens, y como parseExpr la convierte en un AST.

JavaScript — tokenizar y parsear 
// La expresion de ejemplo
var src = '(x empty OR y = "foo") AND NOT z matches @re';

// 1. Tokenizar
var tokens = tokenizeExpr(src);
tokens.forEach(function(t) {
  console.log("  [" + t.t + "] " + t.v);
});

// 2. Parsear a AST
var ast = parseExpr(tokens);
console.log("AST type: " + ast.type);
console.log("Left:  " + JSON.stringify(ast.left));
console.log("Right:"); // NOT (z matches @re)
