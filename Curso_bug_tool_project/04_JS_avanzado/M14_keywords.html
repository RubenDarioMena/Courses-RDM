Widget keywords: chips con validacion

El widget de palabras clave transforma un input de texto en chips visuales. Cada chip se anade con Enter o coma, se borra con Backspace o el boton ✕. Detras de esa interfaz simple hay tres validaciones: cantidad exacta de keywords, unicidad (sin duplicados) y kwOverlap (ningun keyword debe aparecer en el cuerpo del bug). En este modulo desmontamos el widget completo.

⚡ JS Avanzado ~12 min de lectura Nivel: intermedio
1La idea en una imagen

Imagina una etiqueta de equipaje: cada palabra clave es una pegatina que pegas en la maleta. Solo caben un numero exacto de pegatinas (kwCount). No puedes repetir la misma palabra (unicidad). Y ninguna pegatina puede decir lo mismo que la descripcion del contenido (kwOverlap). Si intentas romper esas reglas, la maleta no se cierra.

2wireKeywords: el widget completo

La funcion que conecta el input con los chips

El widget se construye sobre un input de texto normal. La funcion wireKeywords escucha tres eventos: keydown para detectar Enter o coma (anadir chip), keydown para Backspace (borrar ultimo chip) y blur para validacion final.

JavaScript — wireKeywords (esqueleto)
function wireKeywords(input, inst) {
  const wrap = input.closest(".keywords-wrap");
  const chipsBox = wrap.querySelector(".keywords-chips");

  input.addEventListener("keydown", (e) => {
    if (e.key === "Enter" || e.key === ",") {
      e.preventDefault();
      addChip(input, inst);       // anadir palabra clave
    } else if (e.key === "Backspace"
               && input.value === "") {
      removeLastChip(inst);       // borrar ultima
    }
  });
}

El flujo completo

1

Enter o coma → addChip

Al pulsar Enter o coma, el texto del input se convierte en chip. El input se vacia y los chips se re-pintan.

2

Backspace en input vacio → removeLastChip

Si el input esta vacio y pulsas Backspace, se borra el ultimo chip. Es el mismo patron que usan Gmail o Slack.

3

Click en ✕ → removeChip(i)

Cada chip tiene un boton ✕. Al pulsarlo se borra ese chip en especifico por su indice.

4

Despues de cada cambio → revalidate

Tras anadir o borrar, se ejecutan las tres validaciones para mostrar errores en vivo.

3Anadir y borrar chips

addChip: del texto al chip visual

La funcion addChip lee el texto del input, lo limpia con trim() y toLowerCase(), comprueba que no este vacio, que no sea duplicado, y lo aniade al array inst.values.keywords. Despues re-renderiza.

JavaScript — addChip / removeChip
function addChip(input, inst) {
  const v = input.value.trim().toLowerCase();
  if (!v) return;
  const arr = inst.values.keywords || [];
  if (arr.includes(v)) return;  // unicidad
  arr.push(v);
  inst.values.keywords = arr;
  input.value = "";
  renderChips(wrap, inst);
  revalidate(inst);
}

function removeChip(inst, i) {
  inst.values.keywords.splice(i, 1);
  renderChips(wrap, inst);
  revalidate(inst);
}

El truco de la unicidad esta en arr.includes(v) antes de push. Como el array se normaliza a minusculas, "Bug" y "bug" se consideran el mismo keyword.

4Las tres validaciones

kwCount, unicidad y kwOverlap

El widget valida tres cosas distintas. Cada una produce un mensaje de error diferente que se muestra debajo del input.

JavaScript — validacion de keywords
// 1. Cantidad exacta de keywords (kwCount)
if (arr.length !== config.kwCount) {
  errors.push("Debe haber exactamente "
    + config.kwCount + " palabras clave");
}

// 2. Unicidad (sin duplicados)
const set = new Set(arr);
if (set.size !== arr.length) {
  errors.push("No puede haber keywords duplicados");
}

// 3. kwOverlap: ningun keyword aparece en el cuerpo
const body = (inst.values.body || "").toLowerCase();
const overlap = arr.filter(kw => body.includes(kw));
if (overlap.length) {
  errors.push("Estos keywords ya estan en el cuerpo: "
    + overlap.join(", "));
}

kwOverlap evita que el usuario anada como keyword algo que ya aparece en la descripcion del bug. Si el cuerpo dice "el servidor cae a las 3am", el keyword "servidor" no aporta nada nuevo y se rechaza.

5Re-render sin perder foco: refresh()

El problema de re-pintar mientras el usuario escribe

Cuando re-renderizas un widget que contiene un input, el navegador pierde el foco del input. El usuario notaria que el cursor desaparece. La solucion es refresh(): guarda la posicion del cursor, re-pinta el HTML, y despues restaura el foco y el cursor.

JavaScript — refresh() sin perder foco
function refresh(input, inst) {
  // 1. Guardar estado del cursor
  const wasFocused = document.activeElement === input;
  const selStart = input.selectionStart;
  const selEnd = input.selectionEnd;

  // 2. Re-pintar el HTML de los chips
  renderChips(input.closest(".keywords-wrap"), inst);

  // 3. Restaurar foco y cursor
  if (wasFocused) {
    input.focus();
    input.setSelectionRange(selStart, selEnd);
  }
}

Sin refresh(), cada vez que el widget re-renderiza por una validacion o un cambio en otro campo, el usuario perderia el cursor y tendria que volver a hacer clic en el input. Es un detalle pequeno que marca la diferencia entre un widget profesional y uno que frustra.

6Tu primer momento: simular chips

Pulsa Ejecutar para ver como wireKeywords procesa una secuencia de entradas: anade tres keywords, intenta anadir un duplicado (se rechaza) y despues borra uno con Backspace.

JavaScript — simulacion de chips 
// Simular el widget de keywords
var keywords = [];
var kwCount = 3;  // cantidad exacta requerida

function add(v) {
  v = v.trim().toLowerCase();
  if (!v) return "vacio";
  if (keywords.includes(v)) return "duplicado";
  keywords.push(v);
  return "ok";
}
